## Plugin-native JIT routing contract

The Agent Project Compiler plugin keeps a small always-loaded compiler kernel and treats these reference guides as JIT procedural references. Installed/reference-visible does not mean loaded. Resolve the smallest guide set from the active compiler concern, read it before crossing that decision boundary, and do not preload all 20 files for confidence.

When `core-first-governance` is actually available, it remains a separate procedural owner rather than copied compiler policy:

```text
architecture / ownership / authoritative state / reuse / composition / capability / provider / extension material
→ load `core-first-orchestration` for current routing semantics when needed
→ primary compiler/agent loads + applies `core-first-extension-architecture` before freezing the owner/change boundary

real user/external observable claim material
→ route verification to `observable-product-verification` when the host exposes it

material architecture/reuse/ownership conformance
→ route to `core-first-verifier` in a fresh read-only context when feasible

consequential/high-risk/difficult-to-verify implementation
→ route to `independent-review` when triggered
```

If the companion plugin is absent, use this package's existing Core-First/change/ownership authorities and project-native gates; never claim that an unavailable external Skill was loaded. The compiler's packaged references remains product-compilation authority; external Skills remain procedures.
