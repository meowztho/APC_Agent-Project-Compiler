# APC v2.32 — Plugin-Native JIT Routing Findings

## Why v2.32 exists

APC v2.31 already described an installable compiler Skill, but the shipped distribution was still operationally centered on a Custom GPT: one instruction field plus 20 uploaded Knowledge files. After Prompt Compiler became a plugin, that shape left performance and clarity on the table because the runtime can expose a compact Skill and supporting references directly.

## Canonical owner decision

No new compiler policy authority was created. The existing 20 Knowledge files remain canonical detailed owners. `SKILL_NATIVE_COMPILER_GUIDE.md` owns compiler-Skill lifecycle/routing; `KNOWLEDGE_INDEX.md` owns detailed retrieval routing; `AGENT_RUNTIME_PORTABILITY_GUIDE.md` owns provider/plugin binding semantics.

The plugin `skill.md` is a procedural orchestration kernel. Its `references/` directory is a generated byte-identical projection of `Knowledge/`, not a second authority.

## JIT routing change

The plugin now loads:

```text
plugin invocation
→ compact APC kernel
→ material trigger
→ smallest canonical Knowledge reference(s)
→ optional companion Skill only when its trigger is material
→ compile/update/audit
→ evidence/reconstruction/delivery gates
```

This replaces the old practical tendency to treat the full Custom-GPT Knowledge set as one ambient corpus.

## Core-First integration

Core-First Governance remains a separate procedural owner. APC carries only trigger knowledge:

- architecture/ownership/authoritative-state/reuse/composition/capability/provider/extension material → primary agent loads/applies `core-first-extension-architecture`;
- orchestration/freshness/verification routing details → `core-first-orchestration` JIT;
- material architecture conformance → `core-first-verifier`;
- real user/external outcomes → `observable-product-verification`;
- consequential/high-risk/difficult-to-verify implementation → `independent-review`.

APC does not copy the full Governance procedures. If the plugin is unavailable, the packaged Core-First/change/ownership authorities and project-native gates remain the fallback.

## Compatibility

The legacy Custom GPT distribution remains valid. `CUSTOM_GPT_INSTRUCTIONS.md` was intentionally retained as a compatibility surface; v2.32 changes the preferred runtime packaging rather than deleting the old path.

## Drift prevention

`tools/build_plugin_projection.py` regenerates the plugin reference projection from `UPLOAD_MANIFEST.json` + `Knowledge/`. Package verification requires every projected reference to be byte-identical to its canonical source.
