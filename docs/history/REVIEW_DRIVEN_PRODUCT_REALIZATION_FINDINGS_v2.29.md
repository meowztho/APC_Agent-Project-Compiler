# APC v2.29 — Domain-Neutral Review-Driven Product Realization

## Source calibration

A real agent-build report from an interactive product showed useful mechanisms: keeping a representative product path continuously healthy, using reproducible review projections, generating outputs from canonical recipes/producers, and spending substantial effort on finish/fidelity after initial functionality.

The source domain is not generalized. v2.29 preserves only domain-neutral semantics.

## Added mechanisms

1. **Representative Product Path / Heartbeat** — an existing E2E/integration scenario may become a high-information regression heartbeat. It can represent a UI journey, API/CLI workflow, automation, job, data pipeline, generation pipeline, device/runtime path, or another project-specific cross-boundary path. It is rerun after material intersecting changes, not every edit.

2. **Deterministic Review Projection** — a stable input/state/query/view/fixture produces reproducible derived observations (screenshots, renders, reports, diffs, sample outputs, traces, etc.). Review artifacts are consumers/evidence, never Product Truth. Defects are fixed at canonical owners/producers and the projection is regenerated.

3. **Reproducible Producer Pipeline** — source/recipe/authority → generator/transformation/provider → generated artifact → consumer. Generated outputs are normally not canonical edit owners. Durable edits go upstream and are regenerated.

4. **Finish/Fidelity Product Outcomes** — requested or materially implied quality obligations become ordinary PR-* outcomes with plan/Acceptance/evidence. There is no universal POLISH phase and no game-specific art pipeline.

5. **Optional workstreams remain heuristic** — functional/experiential or other parallel streams may help planning, but canonical architecture is still Responsibility → Owner → Capability/Contract.

## Explicit non-goals

No universal game phases, actors, assets, scenes, levels, controls, branches/worktrees, Blender/Python/Meshy toolchain, fixed polish percentage, or "mechanics then art" sequence is introduced.

Core-First Governance is unchanged. Plugin-side ideas remain research/eval candidates only.
